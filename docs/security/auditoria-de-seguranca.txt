## 🕵️ FASE 1: RECONHECIMENTO E ANÁLISE OFENSIVA (RED TEAM)

### VULN-1: Controle de Acesso Quebrado nas rotas mutativas da API Express
- **Severidade:** CRÍTICA
- **Vulnerabilidade:** [OWASP A01:2021-Broken Access Control] | [CWE-287 - Improper Authentication]
- **Anti-Padrão de IA:** A1 (Segurança apenas no cliente) e A2 (Lógica de segurança / middleware desabilitado ou ignorado no backend).
- **Código Vulnerável Original:** As rotas `POST /api/topics`, `PUT /api/topics/:slug` e `DELETE /api/topics/:slug` no backend Express realizavam mutações no banco de dados Supabase utilizando o cliente administrativo configurado com a `SUPABASE_SERVICE_ROLE_KEY` (ignora RLS), sem verificar nenhum tipo de token de acesso.
- **Exploit (PoC):**
  ```bash
  curl -X DELETE http://localhost:4000/api/topics/zumbi-dos-palmares
  ```
  Isso apagaria o verbete do banco de dados sem nenhuma autenticação, bastando conhecer a URL e o slug do verbete.
- **Impacto:** Destruição em massa de dados, pichação do acervo (defacing) e total violação da integridade da enciclopédia.

---

### VULN-2: Abuso financeiro e de recursos na API de Geração de Imagem
- **Severidade:** ALTA
- **Vulnerabilidade:** [OWASP A01:2021-Broken Access Control] | [CWE-287 - Improper Authentication]
- **Anti-Padrão de IA:** A7 (Permissões excessivas / bypass de verificação de token).
- **Código Vulnerável Original:** A rota `/api/gemini/image` continha a seguinte checagem fraca:
  ```javascript
  const authHeader = req.headers['authorization'];
  if (!authHeader) {
      return res.status(401).json({ error: 'Access denied: ...' });
  }
  ```
- **Exploit (PoC):**
  ```bash
  curl -X POST -H "Authorization: Bearer qualquer-coisa" -H "Content-Type: application/json" -d '{"topic": "Quilombo"}' http://localhost:4000/api/gemini/image
  ```
  Passar qualquer string no header `Authorization` era suficiente para burlar a proteção e acionar o modelo pago Imagen 3.0 no backend.
- **Impacto:** Gastos financeiros significativos e exaustão de cotas da chave de API da Gemini da Wikipreta.

---

### VULN-3: DoS por paginação descontrolada na listagem de verbetes
- **Severidade:** MÉDIA
- **Vulnerabilidade:** [OWASP A05:2021-Security Misconfiguration] | [CWE-400 - Uncontrolled Resource Consumption]
- **Anti-Padrão de IA:** A10 (Paginação sem limite superior de itens).
- **Código Vulnerável Original:**
  ```javascript
  const { page = 1, limit = 10, search = '' } = req.query;
  const offset = (page - 1) * limit;
  ```
  O parâmetro `limit` era passado direto do cliente para o Supabase sem validação de tamanho máximo.
- **Exploit (PoC):**
  ```bash
  curl "http://localhost:4000/api/topics?limit=500000"
  ```
  Isso forçaria o banco a tentar listar e serializar toda a base de dados de uma vez só.
- **Impacto:** Exaustão de memória no Node.js, travamento temporário do banco de dados Supabase e indisponibilidade do serviço (Denial of Service).

---

### VULN-4: Falta de Validação de Tamanho de Entrada em Payloads
- **Severidade:** MÉDIA
- **Vulnerabilidade:** [OWASP A03:2021-Injection] | [CWE-20 - Improper Input Validation]
- **Anti-Padrão de IA:** A8 (Payloads aceitos sem validação ou sanitização).
- **Código Vulnerável Original:**
  Na rota de criação e edição (`POST /api/topics` e `PUT /api/topics/:slug`), os dados de `title` e `content` eram inseridos diretamente no banco sem restrições de comprimento de caracteres (`maxLength`).
- **Exploit (PoC):**
  Enviar um payload de `content` com 50 megabytes de texto lixo.
- **Impacto:** Esgotamento do espaço em disco contratado no banco de dados Supabase, além de travamento ou renderização deformada no frontend ao carregar o texto.

## 🛡️ FASE 2: MITIGAÇÃO E DEFESA EM PROFUNDIDADE (BLUE TEAM)

As seguintes blindagens foram implementadas nos arquivos do projeto:

### 1. Modificações no Backend: [api/index.js](file:///d:/projects/react_projects/wikipreta.org/api/index.js)
- **Validação de Token JWT**: Implementação de middleware `requireSupabaseAuth` que extrai o token JWT da requisição e o valida contra o servidor do Supabase Auth por meio da chamada segura `supabase.auth.getUser(token)`.
- **Prevenção de DoS e Limite de Taxa**: Acoplamento de um middleware simples de rate limiting em memória (`rateLimiter`) para impedir abuso de requisições maliciosas.
- **Validação de Payload Estrita**: Implementação de `validateTopicPayload` que restringe o tamanho do título a no máximo 100 caracteres e o conteúdo do verbete a no máximo 10.000 caracteres.
- **Restrição de Paginação**: Capamento estrito do tamanho máximo de itens solicitados para 100 registros.

**Trecho de código das correções implementadas:**
```javascript
// 🔒 SEGURANÇA [VULN-DoS]: Evita abuso de chamadas de custo de IA / DoS
if (record.count > maxRequests) {
  return res.status(429).json({ error: 'Too many requests. Please try again later.' });
}

// 🔒 SEGURANÇA [VULN-BAC]: Nega acesso a operações privilegiadas sem token
const requireSupabaseAuth = async (req, res, next) => {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1];
  if (!token) return res.status(401).json({ error: 'Access denied: No token provided' });
  
  const { data: { user }, error } = await supabase.auth.getUser(token);
  if (error || !user) return res.status(403).json({ error: 'Access denied: Invalid or expired token' });
  req.user = user;
  next();
};

// 🔒 SEGURANÇA [VULN-DoS]: Rejeita payloads massivos de texto
const validateTopicPayload = (req, res, next) => {
  const { title, content } = req.body || {};
  if (req.method === 'POST' && title.length > 100) return res.status(400).json({ error: 'Title is too long' });
  if (content && content.length > 10000) return res.status(400).json({ error: 'Content is too long' });
  next();
};
```

### 2. Injeção de Autenticação no Frontend
- **Modificação no Service**: [services/databaseService.ts](file:///d:/projects/react_projects/wikipreta.org/services/databaseService.ts) foi atualizado para recuperar a sessão ativa com `supabase.auth.getSession()` e injetar o token JWT atual no cabeçalho `Authorization: Bearer <token>` nas requisições mutativas.
- **Modificação na Tela Administrativa**: [pages/AdminDashboard.tsx](file:///d:/projects/react_projects/wikipreta.org/pages/AdminDashboard.tsx) foi modificado para recuperar o token correspondente da sessão ativa e enviá-lo de forma segura na chamada HTTP `DELETE`.
